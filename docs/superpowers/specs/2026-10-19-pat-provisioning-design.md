# PAT 检测专用账号、自动补号与状态分类

状态：用户已于 2026-10-19 确认设计，进入实施。本目录不是 Git 仓库，不初始化仓库、不提交。

## 1. 已确认的目标与边界

用户希望系统从自己管理的可选账号中，自动挑选少量账号，在全新独立浏览器中登录 GitHub，创建用于公开资料检查的 PAT；真正失效后自动补充。PAT 来源账号作为检测专用账号，与 WorkBuddy 候选隔离。账号列表增加可区分用途和处理进度的分类。

- 默认维护 1 个有效 PAT，目标数量可配置，首版范围 1–3 个。未过期但额度冷却中的 PAT 仍计入维护数量，不触发补号。
- 默认有效期 30 天，只访问公开资料，不申请私有仓库、写入、组织管理或工作流权限。优先 fine-grained PAT，限定公共资源只读；无法确认页面实际权限时停止，不降级申请更大权限。
- 复用项目专用 Chromium 的启动和隔离方式，不连接用户已有浏览器，不导入 Cookie。PAT 登录单独实现状态机，不能解除现有 WorkBuddy OAuth 的回调和身份保护来复用它。
- TOTP 使用账号已有密钥即时生成；邮箱验证码交给用户。验证码挑战、安全检查和无法识别的页面需人工处理，不绕过。
- 额度用尽遵守恢复时间；次级限流也退避，不通过不断新增或切换账号规避平台限制。网络错误、普通 403 不视作 PAT 已失效。
- 自动补号仅在用户开启此功能后的检测任务中按需执行，或用户明确点击“补充检测账号”时执行；不增加独立后台定时登录任务。
- 不承诺公开资料可访问等于没有登录限制或风控。

## 2. 方案选择

选择“独立 PAT 专用池 + 独立状态 + 现有账号页分类”。备选方案“复用 selectedAt 作为 PAT 使用标记”会混淆 WorkBuddy 成功与 PAT 用途，并与现有自动释放逻辑冲突，因此不采用。也不把每个 PAT 状态都平铺为顶层标签，避免顶栏过长。

## 3. 页面分类与状态

沿用用户截图的蓝白顶部标签样式，主分类为：

`全部账号 | 待选用 | 已选用 | PAT 专用 | 处理中 | 需留意`

- 全部账号：所有未删除账号。
- 待选用：通过最近有效公开检测、未被占用、未选用、没有 WorkBuddy 成功映射、不是 PAT 专用的账号。
- 已选用：保留现有选用含义；不把 PAT 创建成功伪装成 WorkBuddy 使用成功。
- PAT 专用：所有保留了 PAT 专用用途的账号，包括失效、待处理、停用的来源账号。
- 处理中：正在执行的 PAT 准备或 WorkBuddy 授权账号；等待人工处理用明确子状态表示。
- 需留意：公开检查异常、PAT 明确失效/创建失败/需人工处理、WorkBuddy 失败或结果未知。正常额度冷却不算账号异常。

主分类是可交叉的筛选视图，不宣称各项计数相加等于全部数量。单行同时展示“公开状态”“账号用途”“任务/PAT 状态”，不再用一个状态代表所有含义。

PAT 专用分类内部增加状态筛选：

| 状态 | 含义 | 后续行为 |
| --- | --- | --- |
| 准备中 | 已锁定账号，正在登录或创建 PAT | 显示当前步骤，可停止 |
| 可用 | PAT 已落盘且身份、权限、有效性验证通过 | 可供公开资料检查使用 |
| 额度冷却 | 有效 PAT 的额度耗尽或接口要求退避 | 显示恢复时间，等待后重新检查额度 |
| 已失效 | 已过期或确认认证凭据无效 | 不再使用；按目标数量自动补充 |
| 需处理 | 邮箱验证、登录失败、未知页面或创建结果不确定 | 显示具体原因和继续/停止操作 |
| 已停用 | 用户明确停用该来源 | 不用于检测，不自动重新启用 |

“待补充”是池级提示（有效数量不足），不伪造成某个具体账号的生命周期状态。

详情继续使用居中弹窗；查看模式不直接修改配置。展示 PAT 来源、创建时间、到期时间、额度和最近错误；不返回或展示 PAT 明文。独立“检测配置”弹窗负责自动补号开关、目标数量、30 天有效期说明及启用确认。

## 4. 自动补号与账号隔离

1. 检测开始后，先使用已验证的专用 PAT；所有有效 PAT 处于限流退避时等待，不补号。
2. 缺少有效 PAT 时，事务内从可选账号中随机挑选并锁定。后端重新校验资格，不能只依赖前端计数。
3. 开始前标记 PAT 专用，其他窗口、WorkBuddy 预览/启动以及通用选用接口均排除此账号。
4. 启动干净浏览器，核对官方 GitHub 地址和实际登录身份；只向官方受识别表单填入账号、密码、TOTP。
5. 核对 PAT 名称、所属账号、30 天有效期、公共资源只读权限后提交一次创建。
6. 读取一次性 Token 后立即加密落盘为“待验证”，再调用只读身份接口核对用户名。成功才变成“可用”，网络失败保留待验证状态，不重新创建。
7. 一轮补充最多尝试 3 个不同候选；同一候选不在该轮重复尝试。失败记录原因，不把登录失败直接标记成 GitHub 封禁。
8. 邮箱验证、验证码挑战或疑似平台级安全限制暂停该轮，不通过换下一个账号绕过。没有候选时显示“可选账号不足”，不偷偷放宽已使用/已占用/检测过期条件。

临时浏览器锁必须等待浏览器实际关闭后释放。PAT 专用用途与临时锁分开：关闭、失败、过期、重启都不能让该账号意外回到 WorkBuddy 候选。

创建提交后结果未知时标记“需处理”，不得重复提交创建，也不得声称远端未产生 Token。用户手动取消专用用途需二次确认并说明远端 Token 不会自动撤销；仍有有效或结果未知 Token 时禁止直接释放为普通候选。

## 5. 检测与配额

- 读取 GitHub 返回的实际 limit、remaining、reset、Retry-After，不硬编码所有认证请求一定有 5,000 次额度。
- 额度耗尽时保留当前账号和已完成进度，显示北京时间恢复时间；可取消。恢复后先重试当前未完成账号，不从头重复扫描。
- 401 或已到期可判定凭据失效；403、429 结合头和受限类别判断。权限拒绝、网络错误、5xx 与次级限流单独处理，不触发无限补号。
- PAT 认证失败或共享配额受限不能覆盖被检查账号之前的有效公开状态；请求诊断保存到任务/专用 PAT 记录。
- 检测继续串行并限制频率。无 Token、无候选时明确说明；不静默退回匿名扫描，也不自动登录整池账号。
- 服务重启后保留进度和结果，将未完成任务标记为中断，用户点击继续后恢复；不在启动时自动登录或创建 PAT。

## 6. 模块与持久化

- 独立 PAT 存储模块：加密 Token、账号绑定、生命周期、实际配额、有效期和验证记录；复用 master.key，禁止生成新密钥替换既有密钥。
- 独立补号服务：数量目标、候选事务锁、串行任务、人工处理/取消/恢复、幂等与失败次数上限。
- 独立 PAT 浏览器状态机：登录、TOTP、重新认证、权限验证、创建提交、一次性读取。与 WorkBuddy 的 OAuth 证据状态机分离。
- 检测器集成 PAT 提供器和可取消的配额等待；任务进度持久化，保留旧接口兼容字段并增加阶段、恢复时间。
- 账号列表仅返回用途与安全元数据；PAT、密码、Cookie、TOTP 和敏感响应不得进入列表接口、日志、截图或测试产物。
- 更新 Store 通用选用、WorkBuddy 候选及启动事务校验、前端 eligible 三个边界，防止只改 UI 而后端仍可选中专用账号。

保留现有主题：背景 #f6f8fb、正文 #19273b、蓝色 #315de6、绿色 #187458、琥珀色 #9a640e、红色 #b33f48；使用现有白色表面与边框 token。标题/正文沿用 Segoe UI / Microsoft YaHei，计数、额度和时间用现有 Consolas 数字样式。

状态必须含文字和图标，不仅依赖颜色。键盘可用、焦点可见；等待不锁住取消按钮；冷却显示明确恢复时间，不使用永久转圈伪装正在处理。状态过渡约 150–200ms，遵守 reduced-motion，不因计数变化导致布局跳动。
