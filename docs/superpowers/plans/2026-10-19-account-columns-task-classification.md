# 账号列表列管理与任务分类改版任务

状态：已获用户「开始修改吧」授权，已实施并完成本地验收。验证记录见 [账号列表与任务分类验收](../../account-columns-verification.md)。

## 目标

保留紧凑简约风格，拆清账号信息、来源分组、自定义用途标签、公开检测、任务归属和任务执行结果。任务范围以 WorkBuddy2api 与 PAT 管理为主。

## 确认的用户要求

- TOTP 恢复为独立列。
- 增加时间列，基于数据库真实字段。
- 提供列表列管理，勾选决定显示。
- 移除“用途与任务”混合列，标签单独展示。
- 重整当前“全部账号 / 待选用 / 已选用 / PAT 专用 / 处理中 / 需留意”分类。
- 最初先整理方案，后经用户明确授权开始修改并完成实施。

## 列方案

默认顺序：勾选、账号信息、来源分组、标签、TOTP、检测状态、入库时间、操作。

| 列 | 默认 | 规则 |
|---|---|---|
| 勾选 | 显示、固定 | 批量操作入口 |
| 账号信息 | 显示、固定 | 用户名与邮箱，不再嵌入 TOTP |
| 来源分组 | 显示 | 一个账号一个来源；可整理分类 |
| 标签 | 显示 | 仅用户维护的用途标签，多标签折叠为前几个及“+N”，可展开全部 |
| TOTP | 显示 | 已设置 / 未设置，表示是否保存密钥，不承诺密钥有效；列表不展示密钥或动态验证码 |
| 检测状态 | 显示 | 未检测 / 公开可访问 / 公开不可访问 / 无法判断，错误原因可查看 |
| 入库时间 | 显示 | 本工具新增或导入时间 |
| 最近检测时间 | 可选 | 与检测状态分开，开启后不在状态单元格重复显示 |
| 选用时间 | 可选 | 当前选用标记的时间，不等同授权成功时间 |
| 任务状态 | 普通视图隐藏；WorkBuddy/PAT 视图首次默认显示 | 专门显示对应任务执行状态，不能恢复成混杂的“用途与任务”列 |
| 最近 WorkBuddy 处理结束时间 | 可选 | 本账号最近一次非跳过任务的结束时间，可能成功也可能失败 |
| WorkBuddy 关联时间 | 可选 | 成功保存账号与目标关联的时间；有多个关联时显示最近一次，详情展示全部 |
| PAT 到期时间 | PAT 视图首次默认显示，其他隐藏 | 取当前 PAT 记录，空值为“—” |
| 备注 | 可选 | 截断并提供完整内容入口 |
| 移除时间 | 仅回收站默认显示 | 其他视图不展示 |
| 操作 | 显示、固定 | 检测、详情、编辑等入口 |

“显示列”位于列表工具栏右侧。面板按基本信息、检测、任务与时间分区，勾选立即生效，提供恢复默认。首版只做显隐，不增加拖拽排序。

偏好按全部账号 / WorkBuddy / PAT / 回收站视图分别保存在当前浏览器，刷新后保留。浏览器存储不可用或配置损坏时使用默认列，不能影响列表加载。仅保存列 ID 等界面配置，不保存账号或凭据。自定义偏好优先于视图默认。

所有时间采用北京时间 YYYY-MM-DD HH:mm；无值显示“—”，可查看完整时间。支持入库时间与最近检测时间排序，空值固定末尾，同时间以账号 ID 稳定排序。

## 数据库只读核验

| 数据表与字段 | 实际含义 | 当前非空记录数 | 使用建议 |
|---|---|---:|---|
| accounts.createdAt | 账号进入本地工作台的时间 | 102 | 默认入库时间；不是 GitHub 注册时间 |
| accounts.checkedAt | 已保存公开检测结果的时间 | 102 | 可选检测时间；不是最后一次请求尝试时间 |
| accounts.selectedAt | 当前选用标记时间 | 6 | 可选；释放选用后会清空 |
| accounts.deletedAt | 移入回收站时间 | 0 | 回收站列 |
| workbuddy_jobs.createdAt / finishedAt | 整个批次创建 / 结束时间 | 20 / 20 | 任务详情；不当作每个账号处理开始时间 |
| workbuddy_items.createdAt / finishedAt | 账号加入任务 / 处理结束时间 | 229 / 229 | 最近有效处理结果；跳过记录不覆盖真正执行的结果 |
| workbuddy_mappings.createdAt | 成功保存关联时间 | 1 | WorkBuddy 关联时间 |
| pats.createdAt | 本地 PAT 记录建立时间 | 4 | PAT 详情；不是确认生成 Token 的时间 |
| pats.expiresAt | PAT 到期时间 | 2 | PAT 视图可选时间列 |
| pats.resetAt | API 额度重置时间 | 2 | PAT 管理详情 |
| pats.retryAt | 重试时间 | 0 | 冷却提示，不充当通用时间列 |

账号表不存在 updatedAt。integration_targets.updatedAt 是部署配置修改时间，不能当作账号修改时间。操作记录也不能直接替代“最后修改时间”，因为其中包含检测、复制之外的多种行为，并可能有历史缺口。首版不新增这些时间字段，不推算不存在的历史时间。

## 分类方案：当前任务归属 + 独立执行状态

主分类建议：全部账号 / 未分配 / WorkBuddy2api / PAT 专用 / 其他已分配。

除全部账号外，主分类互斥，每个有效账号只计入一项，数量之和等于有效账号总数。分组、标签和公开检测仍是独立筛选维度。

推荐归属规则，按顺序判定：

1. PAT 专用：patDedicated=1，或存在可识别的 PAT 当前保留任务。
2. WorkBuddy2api：有真实的 workbuddy_mappings 关联，或能通过任务表确认的当前 WorkBuddy 占用。
3. 其他已分配：具有 selectedAt 的剩余账号，以及无法关联到已知任务的遗留占用账号；后者显示“占用来源待核对”。保留历史 purpose 在详情，不根据备注、标签或用途文字猜测它属于哪个项目。
4. 未分配：没有以上当前用途或任务占用。失败、跳过且已经释放的历史 WorkBuddy 任务不会永久占用此分类。

快照：全部 102 = 未分配 94 + WorkBuddy2api 1 + PAT 专用 2 + 其他已分配 5。当前没有保留中的任务。此为读取时快照，实施时必须重新计算，不硬编码。

实施时要对遗留 reservedBy 做任务表关联核验，不能将所有非空值直接叫“WorkBuddy 处理中”。未知占用在“其他已分配”中显示“占用来源待核对”，保持禁止重复选用的现有保护，不归入未分配。多项用途冲突按上述优先级展示一项，详情保留冲突信息，不自动改写用途。

### 二级状态

- WorkBuddy2api：待执行、执行中、待人工处理、已关联。根据任务及账号子项的真实状态派生，不能只看 reservedBy。
- PAT 专用：准备中、待验证、可用、额度冷却、需处理、已失效、已停用。准备中只有在真实任务运行时才叫执行中；有专用标记但无可用记录显示“待准备”。
- 未分配：全部、符合 WorkBuddy 候选条件、符合 PAT 候选条件、暂不满足。复用对应服务的候选规则，并给出缺少 TOTP、未检测、检测过期等具体原因；两种候选集合允许重叠，明确是筛选条件而非互斥主分类。
- 其他已分配：保留人工分配用途和选用时间的详情入口。

WorkBuddy 授权失败、结果未知、访问受限属于任务结果，不能合并成公开检测失败。已经释放的失败账号回到未分配，WorkBuddy 管理页保留完整任务历史及失败/待核对筛选。已有成功关联不因某次后来尝试失败而被覆盖成未使用。

移除顶层“待选用、已选用、处理中、需留意”。不再用“需留意”把公开检查异常、PAT 失效、WorkBuddy 失败混成一项。
