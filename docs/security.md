# 安全加固与入侵防护

本文只描述**当前代码里真实生效的控制**，以及它们挡的是什么。凡是没做的，也一并列出来，避免误以为已经覆盖。

## 攻击面

项目只有两个监听入口，默认都绑定回环地址：

| 入口 | 默认监听 | 谁能访问到 |
| --- | --- | --- |
| 登录工作台 | `127.0.0.1:4318` | 本机；配置了 `ACCOUNT_DESK_ADMIN_ORIGIN` 并由反向代理转发时才会暴露到公网 |
| 对外 API | `127.0.0.1:4319` | 本机；通常经 `ACCOUNT_DESK_API_ORIGIN` 反向代理对外 |

不设置这两个环境变量时，外部网络**无法直连**，剩下的风险来自本机上的其他用户、浏览器里的恶意页面，以及反向代理配置错误。

## 分层的实际控制

### 1. 本机浏览器里的恶意页面

一个恶意网页想打 `127.0.0.1:4318`，会依次被拦住：

- `Host` 白名单：只接受工作台实际端口和开发端口，DNS rebinding（恶意域名解析到 127.0.0.1）会因 `Host` 不符被 403。
- `Origin` 必须精确等于配置的 origin，跨站请求 403。
- 所有 `/api` 请求必须带 `X-Local-Client: account-desk`，跨站简单请求带不了自定义头，带就会触发 CORS 预检，而服务端不返回 CORS 头。
- `SameSite=Strict` 会话 Cookie，跨站请求根本不带 Cookie。
- 写操作另外校验 `X-CSRF-Token`（HMAC 派生自会话令牌，随会话变化）。

以上四类拒绝都会写入安全事件表（`host_rejected` / `origin_rejected`），不是只返回一个 403。

### 2. 猜密码 / 撞库

- 密码用 scrypt 存储，参数带版本（v2 为 N=2^17、maxmem 256 MB），旧库自动升级。
- 管理员用户名与密码**同时**参与一整个 scrypt 运算后才比较。原先先比用户名、用户名不对就跳过 scrypt，网络侧能靠响应时间区分"账号存在"和"密码错误"，现在这条侧信道已关闭。
- **按来源分桶**的尝试计数：每个来源每分钟最多 60 次，最多 2 个并行密码计算，计数跨重启保留。
- 在此之上叠加**递增冷却**：同一来源连续失败第 5 次起锁定 30 秒，之后每多失败一次翻倍（60 s、2 min、4 min、8 min），上限 15 分钟。锁定期内即使密码正确也返回 429。成功登录清零。
- 锁定不再是一个全局开关。曾经所有失败共用一行计数：任何人打 5 次错密码就能把管理员锁在门外，而"登录成功"是唯一清零方式，于是可以永久维持锁定。现在每个来源一个桶；本机回环地址共用 `local` 桶（同一台机器，拆开没有意义）。剩下的一种情况——本机进程持续打错把 `local` 桶锁住——用 `npm run admin:unlock` 或另一个已登录窗口的 `POST /api/auth/unlock` 立刻解除，不需要等 15 分钟。
- 反向代理后若想按真实客户端区分来源，设置 `ACCOUNT_DESK_TRUST_PROXY=1`（等价于 Express 的 `trust proxy = 1`），此时来源取代理链中最靠近服务端的那一跳，同时也会让 `X-Forwarded-Proto: https` 生效，从而下发 `Secure` + `__Host-` Cookie。**不设置时完全不信任转发头**，全部请求视为 `local` 桶。
- 失败与锁定都写入安全事件（`login_failed` / `login_locked` / `login_succeeded` / `admin_unlocked`），事件里带来源桶，便于区分"自己输错"和"有人在打"。

客观地说：这套设计防的是**在线暴力破解**，防不了拿到 `data/` 目录的人。`master.key` 与 `accounts.sqlite` 同目录，能读目录就等于能解全部账号密码，这是加密存储的固有限制，不是登录逻辑的问题。

### 3. 会话被盗

- 会话令牌 32 字节随机，服务端只存 SHA-256 摘要，数据库泄露不等于能直接使用会话。
- Cookie 为 `HttpOnly` + `SameSite=Strict`；HTTPS 域名下使用 `Secure` 与 `__Host-` 前缀。
- 绝对有效期 12 小时；**另加 2 小时空闲超时**，只有真正发过请求才续期，且每分钟最多写一次数据库。
- `GET /api/auth/sessions` 列出所有活动会话（创建时间、最后活动时间、是否当前会话），只返回摘要前 12 位，不返回令牌本身。
- `DELETE /api/auth/sessions` 撤销除当前会话外的全部会话，用于怀疑泄露时的应急处理。
- 修改密码会删除所有会话并签发新会话。

### 4. 反向代理暴露后的公网攻击

- 安全响应头：`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Cross-Origin-Opener-Policy`、`Cross-Origin-Resource-Policy`、`X-Permitted-Cross-Domain-Policies: none`、`Permissions-Policy` 关闭摄像头/麦克风/定位/支付等能力。
- CSP 为 `default-src 'self'`，并显式 `object-src 'none'`、`frame-src 'none'`、`worker-src 'none'`、`form-action 'self'`、`base-uri 'none'`、`frame-ancestors 'none'`。
- 只有配置了 HTTPS 的 `ACCOUNT_DESK_ADMIN_ORIGIN` 且 `Host` 匹配时才下发 HSTS；本机 HTTP 下不下发，避免把浏览器锁到 http 之外的错误状态。
- 请求体上限 2 MB，认证接口单独 8 KB。
- 错误响应统一脱敏：非预期错误只返回"操作失败"，不返回堆栈、SQL 或原始报文。

**来源白名单**（`安全中心 → 访问白名单`）是这一层的最后一道门，在应用里而不是代理里判断：

- 与反向代理规则的区别：代理挡住了应用不知道，"谁被挡了"只留在代理日志里；应用层拦截会写一条 `ip_rejected`，管理员在安全中心能看见，也会推送到通知通道。
- 判定顺序在最前面——先看地址，再看 `Host`、`Origin`、会话。被拒的来源到不了 body 解析和 scrypt。
- 本机回环永不拦截（`127.0.0.0/8`、`::1`）。`npm run admin:unlock`、`data/admin-setup-code.txt`、本地浏览器都从这里进；如果白名单能把自己锁死，一次手滑就是不可恢复的安装。
- 空列表不允许启用（那等于锁死自己），`/0` 也被拒绝（"全部放行"应该用关闭开关表达）。
- 存储行损坏时按空列表处理，即**失败关闭**：宁可本地登录后修复，也不因为一个坏的 JSON 把门打开。
- 拒绝写审计时按来源每分钟一条、全局每分钟 60 条封顶，扫描一个 /16 不会把审计表写爆。
- 支持用 `ACCOUNT_DESK_ADMIN_ALLOW` 播种首次配置；一旦页面保存过，数据库就是唯一来源，环境变量不再介入（否则删掉的旧条目会在重启后复活）。

### 5. 对外 API

- 密钥 32 字节随机，`adk_` 前缀，只存 SHA-256 摘要，创建后仅显示一次。
- 每把密钥每分钟 60 次已认证请求。
- 未认证呼叫不再共享一个计数器。原先服务入口有个"每分钟 600 次"的全局窗口，而计数发生在**认证之前**：任何能连上 4319 的人发 601 个不带密钥的请求，就能让所有合法密钥一起 429。现在匿名呼叫按来源单独计数（每分钟 30 次），已认证请求走自己的密钥额度，两条互不影响；全局只保留每分钟 6000 次的兜底，用来挡分布式洪水，正常流量碰不到。
- **写接口单独限额，按写入条数计量**：导入接口每把密钥每分钟可写入 12000 条账号（单次仍限 1–1000 条）。按调用次数限制会误伤“很多次小批量导入”的正常脚本，按条数计量既不影响批量写入，也把“一次灌 1000 条”的真实成本算进去。可用 `ACCOUNT_DESK_API_WRITE_PER_MINUTE` 调整。
- 密钥无效、越权访问、写入超限都会写入安全事件（`api_key_rejected` / `api_key_scope_denied` / `api_write_throttled`）。
- 公共 API 拒绝任何带 `Origin` 的浏览器请求，也不返回 CORS 头，避免网页直接持密钥调用。

### 6. 安全事件表

`security_events` 记录：初始化管理员、登录失败/成功/锁定、解除锁定、改密、批量撤销会话、自动清理旧会话、身份再验证失败、读取凭据、导出明文、TOTP 启用/关闭/失败、恢复码使用、被拒的 Host 与 Origin、API 密钥拒绝、写入限流，以及"对接地址指向内网"的 `integration_private_target`。

- `GET /api/auth/events?limit=100` 读取，单次最多 2000 条，保留最新 5000 条。
- 只记录"发生了什么"和计数，**不记录密码、设置码、请求正文、会话令牌**。
- 高频来源（例如被刷的无效 API 密钥）5 秒内只记一条，防止日志本身被当成写入放大器。
- 容量从 500 提到 5000 条是有意的：容量太小时，拿到会话的人可以刷几百次无害操作把痕迹挤掉。事件只保留摘要，不含正文，放大容量不会放大泄露面。

**每条记录都带来源**：`ip`（真实客户端地址，仅在开启 `ACCOUNT_DESK_TRUST_PROXY=1` 时采用转发头）、`ua`（完整 User-Agent，截断到 300 字符）、`method`（`password` / `password+totp` / `password+recovery` / `session` / `setup` / `none`，即"靠什么方式通过认证"）、`target`（涉及的账号或主机名）。`admin_sessions` 与 `credential_access` 同样补了 `ip`/`ua`，会话表另有 `method`。

读取接口额外返回 `agent` 字段，是把 UA 解析成「Chrome 141 · Windows 11」这类短标签的结果。解析在服务端做一次，前端只负责显示，避免两端对同一串 UA 给出不同解释。旧记录（功能上线前写入）这四列是 `NULL`，界面显示为"来源未记录"，不做任何猜测。

### 7. 读取明文凭据：二次验证 + 审计

`POST /api/accounts/:id/secrets`（查看密码、TOTP、验证码）与 `POST /api/accounts/export`（导出 TXT）是唯一会把明文送出系统的接口，单靠会话 Cookie 就能读，是"出事会真疼"的缺口。现在两道约束：

- **再认证（step-up）**：先调 `POST /api/auth/reauth` 提交登录密码（启用 TOTP 时还需动态码），换一个 5 分钟有效的令牌，放在 `X-Reauth-Token` 里。令牌只存摘要、**绑定签发它的那个会话**，换个浏览器或换一个会话都不认。过期后再次读取要重新输密码。没有令牌返回 `403` + `code: REAUTH_REQUIRED`，界面据此弹出"确认身份"。
- **一次授权最多读 5 次**。令牌不是"再输一次密码，然后随便导"，而是"刚刚确认过身份"。用完 5 次即失效，界面自动再次弹窗。计次发生在**成功读取之后**，参数错误、选中已删除账号这类被拒的请求不消耗额度。
- **审计**：每次成功读取写两处。`credential_access` 表记结构化明细（时间、动作 `secrets`/`export`、**具体账号标识**、条数、会话摘要前 12 位），保留 2000 条；`security_events` 记一行概览，出现在安全中心的「安全事件」与「操作日志」。导出会把账号列表写进 `accountLabel`（最多 20 个，超出标注总数），因为"导出了 1 条"无法回答"到底是谁被带走了"。**被拒绝的读取不写审计**，避免把失败的尝试误记成"读过"。
- 再认证的密码校验同样计入递增冷却，猜密码不会绕过锁定。

设计取舍：5 分钟内多次查看只输一次密码，避免"每点一下都要输"导致用户去关功能；代价是这 5 分钟窗口内最多 5 次读取，且集中在同一会话，泄露面比"无限复用"小得多。

### 8. 管理员两步验证（TOTP）

- 默认关闭，开启后登录与再认证都需要 6 位动态码（±1 个 30 秒窗口容忍时钟偏差）。
- **动态码不可重放**：接受一个码后会记下它所属的时间步，同一个步内再次提交直接拒绝。否则被肩窥或从日志里捞到的码，在剩余窗口内还能再用一次。
- 密钥 160 位随机，**加密存储**（与账号密码同一把 `master.key` 加密的 AES-256-GCM），不落明文。
- 绑定是分两步的：先 `POST /api/auth/totp/setup` 生成待确认密钥，再用一个能通过的动态码 `POST /api/auth/totp/enable` 才真正启用。**半途中断的设置永远处于"未启用"**，不会把人锁在门外。
- 启用时一次性生成 8 个恢复码，只显示一次，库里只存 SHA-256 摘要，**每个只能用一次**，用掉即作废并记 `recovery_code_used`。
- 关闭需要登录密码 + 当前动态码（或恢复码），不能只凭会话关闭。
- 密码对但没有码不算一次失败（调用方只是还没被问），码错才计入锁定。
- 恢复方式：`npm run admin:reset` 会同时清空 TOTP 与恢复码，重新生成一次性设置码；账号库与 API 密钥不受影响。

### 9. 数据目录权限

这是比所有登录控制都更靠近根子的一层：`master.key` 与 `accounts.sqlite` 同目录，**能读目录就能解全部密码**。

- Windows 上应用写的 `mode:0o600` 不生效，新建目录默认从父目录继承 `Authenticated Users: Modify`，即本机任何登录账户都能读密钥。
- `npm run harden:data` 把它收紧为：当前用户、`SYSTEM`、`Administrators` 完全控制，移除 `Authenticated Users` 与 `Users`。幂等，可重复执行；先授予当前用户再移除继承，避免中途把自己锁在外面。
- `npm run check:data` 只检查不修改，权限过宽时退出码为 1，适合放进部署脚本或 CI 自检。
- Linux/macOS 上脚本改为目录 `700`、目录内文件 `600`。
- **备份目录同样敏感**：备份必须带 `master.key`（否则恢复无意义），所以它和 `data/` 等价。`npm run backup` 默认写到 `backups/` 而不是继承宽权限的 `output/`，并在复制后立刻执行同一套收紧（失败即非零退出）。`npm run harden:data -- --dir <备份目录>` 可对历史备份补做收紧。

### 10. 推送通知

登录、导出、被探测这些事发生时，除了写库还要"当场告诉人"。侧边栏「通知推送」进去是六个小页面——推送通道、发送记录、定时巡检、群机器人、指令、消息记录——各自只回答一个问题，配好一条通道、打开它右上角的开关就开始推送。一条通道都没有时，四种方式会以「未添加」卡片列出来，拨开开关就是添加入口。支持四种通道：

| 类型 | 配置 | 说明 |
|---|---|---|
| 邮件 | SMTP 主机、端口、账号、授权码、发件人、收件人（≤10） | 465 端口自动走 TLS；适合留档 |
| 钉钉机器人 | Webhook + 可选加签密钥 | 加签走 `HMAC-SHA256(secret, timestamp\nsecret)`，URL 参数带 `timestamp`/`sign` |
| 飞书机器人 | Webhook + 可选加签密钥 | 加签走 `HMAC-SHA256(timestamp\nsecret, "")`，签名放进请求体 |
| 通用 Webhook | 回调地址 + 可选 Bearer 令牌 | POST `{ title, text }`，可接自建服务 |

- **按类别订阅**：登录与解锁 / 账号与安全设置 / 凭据读取与两步验证 / 异常与渗透迹象 / 巡检与播报，五组可自由勾选。自动清理旧会话归入"安静"类，永不出站。
- **密钥加密存储**：SMTP 密码、加签密钥、Bearer 令牌与账号密码用同一把 `master.key` 加密；读取接口只返回 `••••••`，编辑时留空表示"不修改"，不会被空值覆盖。
- **只收 https**：回调地址必须是 https（本机回环允许 http），避免令牌走明文。
- **防刷屏**：同一种事件 60 秒内只推一次，单通道每分钟上限 20 条。暴力破解会变成"一条消息 + 后面被合并"，而不是一千条。
- **不阻断业务**：发送在事件写入之后异步进行，失败只记在通道的 `lastError` 与发送记录里，绝不让"推送失败"变成"登录失败"。
- 每条通道都能「测试」，这是唯一能在出事前确认 Webhook 或授权码有效的方式。
- 发送记录保留 2000 条，可在同页查看成功/失败与失败原因。

注意：通知依赖本机出网。若部署在无外网的内网环境，用「通用 Webhook」指向内网告警服务即可，那条通道不需要公网。

### 11. 机器人

「群机器人」页面把"问一句就有人答"接到群里，「定时巡检」页面负责每天自动跑一次。方向上分两条：**出站**是巡检报告，**入站**是群里的指令。机器人、指令、消息记录各占一页：前者管"哪些群接进来了"，后者是说明书，最后一页才是谁问过什么。

| 平台 | 入站校验 | 回复方式 |
|---|---|---|
| 钉钉 | 加签 `HMAC-SHA256(appSecret, timestamp\n appSecret)`，时间戳须在 1 小时内 | 同步回 HTTP 响应体（`msgtype: text`） |
| 飞书 | URL 校验回 `challenge`；配了 Encrypt Key 则校验 `sha256(timestamp + nonce + key + body)` | 回 `{code:0}`，再用 `tenant_access_token` 调 `im/v1/messages` |
| 通用 Webhook | `Authorization: Bearer <密钥>`，密钥必填 | JSON `{ reply }` |

- **只读**：能查数量、状态、近 24 小时事件，能触发检活与播报，**任何回复都不含密码或 TOTP 种子**。这是刻意设计——群消息会被转发、截图、归档到本服务控制不了的地方。
- **入口凭证在 URL 里**：`/bot/hook/<43 字符>`，随机 32 字节，数据库只存 SHA-256 摘要。怀疑泄露时「换地址」立即作废旧值。
- **限流**：单机器人 20 条/分钟，全局 120 条/分钟，检活 5 分钟只启动一次（避免用聊天指令打满 GitHub 配额）。
- **回调地址必须是公网可达**：服务只监听回环，钉钉/飞书的服务器访问不到 `127.0.0.1`。先设 `ACCOUNT_DESK_API_ORIGIN=https://…`，再把 `https://…/bot/hook/…` 填进平台。页面上检测到本机地址会直接给黄色提示。
- **每日巡检**：到点后先检查超过设定天数未检查的账号，结束后推一份报告。报告只发给勾选了「巡检与播报」的通道，不与登录告警混在一条时间线里。

## 明确没做的事

- **没有自动封禁**。白名单是静态规则，不会因为某个来源失败多次就自动加入黑名单；登录锁定是时间性的，也不会永久拉黑。
- **白名单不覆盖对外 API**。它只作用于工作台（4318）；`/api/v1/*` 仍由 API 密钥与按来源限额保护，机器人回调也走公网端口。
- **没有自动封禁**。锁定是时间性的，不会永久拉黑来源。
- **没有硬件密钥（WebAuthn）**。第二因子是 TOTP，不是 U2F/FIDO2。
- **凭据留在剪贴板**。复制密码后由系统剪贴板保管，服务端无法控制其生命周期。
- **TOTP 不防实时钓鱼**。动态码在 30 秒内可被转发使用；FIDO2 才能绑定来源。

## 自检清单

```bash
# 1. 未登录时接口应 401，且不带 X-Local-Client 应 403
curl -s -o /dev/null -w "%{http_code}\n" -H "X-Local-Client: account-desk" http://127.0.0.1:4318/api/accounts

# 2. 伪造 Host 应 403
curl -s -o /dev/null -w "%{http_code}\n" -H "Host: evil.test" http://127.0.0.1:4318/

# 3. 连续失败应出现递增冷却（429 的 Retry-After 会变大）
curl -s -o /dev/null -w "%{http_code} %{header_json}\n" \
  -H "X-Local-Client: account-desk" -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"wrong"}' http://127.0.0.1:4318/api/auth/login

# 4. 数据目录权限（过宽时退出码 1）
npm run check:data

# 5. 凭据读取缺少再认证应 403 + REAUTH_REQUIRED（需先登录并带上 Cookie）
curl -s -b cookie.txt -H "X-Local-Client: account-desk" -H "X-CSRF-Token: <token>" \
  -X POST http://127.0.0.1:4318/api/accounts/<id>/secrets

# 6. 备份目录权限（备份后应只剩当前用户 / SYSTEM / Administrators）
npm run harden:data -- --dir backups/manual-<时间戳> --check

# 7. 匿名请求不应影响合法 API 密钥：连发 40 次后，带密钥仍应 200
for i in $(seq 40); do curl -s -o /dev/null http://127.0.0.1:4319/api/v1/groups; done
curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer adk_..." http://127.0.0.1:4319/api/v1/groups

# 8. 被锁在外面时（本机来源被连续失败锁住）
npm run admin:unlock
```

登录后在浏览器控制台执行 `fetch('/api/auth/sessions').then(r=>r.json())` 可查看当前所有会话；`fetch('/api/auth/credentials').then(r=>r.json())` 可查看凭据读取记录。
