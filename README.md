# GitHub 账号工作台

本机运行的中文 Web 账号管理工具。支持账号整理、公开状态检查、选用标记，以及 WorkBuddy2api 国际版的可见浏览器 GitHub OAuth 授权。自动填写已保存的密码和 TOTP，异常自动重试，超过次数或时间上限后记录原因并处理下一个账号。

## 启动

需要 Node.js **22.15 或更新版本**（推荐 Node.js 24 LTS）。Windows 可双击 `start.cmd`，随后打开 **http://127.0.0.1:4318**。保持启动窗口运行，关闭窗口或 Ctrl+C 可停止服务。

也可以在项目目录执行：

```powershell
npm ci
npm run browser:install
npm run build
npm start
```

开发模式：`npm run dev`，打开 http://127.0.0.1:5173 。工作台后端默认端口为 4318，对外 API 默认端口为 4319，开发前端端口为 5173。两个后端入口均只监听 `127.0.0.1`。端口被占用时请先关闭另一个工作台实例。

## 对外 API

侧栏「API 管理」可创建、编辑、停用、删除独立 API Key，并复制调用示例。支持账号 JSON/文本导入、读取分组与标签、权限与有效期、限流和 24 小时幂等重试；完整密钥仅创建时显示一次。

仅公开 API 时，设置 `ACCOUNT_DESK_API_ORIGIN`，通过 HTTPS 反向代理仅转发 `/api/v1/*` 到 API 端口 4319，管理工作台通过 SSH 隧道访问。也支持同一域名同时提供登录后台与 API，见下面的后台鉴权说明。具体请求格式见 [API 文档](docs/public-api.md)，仅 API 代理示例见 [Caddy 配置](deploy/Caddyfile.api)。

## 账号导出

在「账号管理」顶部点击「导出账号」，选择「已勾选账号」或「当前筛选结果」；勾选后的操作栏也提供「导出选中」。跨页勾选会一起导出，筛选结果覆盖所有分页，并保留当前排序。搜索、账号分类、检测状态、来源分组、用途标签和两步验证条件同时生效；不包含回收站账号。

导出 UTF-8 TXT，每行格式为 `邮箱----密码----用户名----TOTP密钥`，未设置 TOTP 时该字段留空，可按现有导入规则分批导入（每批最多 1000 行、1 MB）。文件包含明文账号密码和 TOTP 密钥，分组、标签和检测结果不包含在内。字段含换行或 `----` 时会提示对应账号并停止导出，避免生成无法正确导入的文件。导出仅供已登录管理员使用，不生成服务器端导出文件。

## 后台登录

首次启动使用数据目录中的 `admin-setup-code.txt` 一次性码设置管理员，无默认密码。后台和内部接口均需要登录，顶栏支持修改密码与退出。密码丢失时先停服务，再执行 `npm run admin:reset`；账号与 API 密钥保留。

后台也可通过 HTTPS 域名访问：设置 `ACCOUNT_DESK_ADMIN_ORIGIN`，使用 [同域名 Caddy 配置](deploy/Caddyfile.full) 将 `/api/v1/*` 转到 API，其余请求转到登录后台。详见 [后台鉴权与部署文档](docs/admin-auth.md)。

## 安全中心

侧边栏「安全中心」分五个标签，每个标签用自己的列表形态，避免几类记录长得一模一样：

- **登录会话**：设备卡片，一张卡一台设备，带 IP、设备、认证方式与到期时间，可单独「下线」或一次下线其他全部。
- **登录记录**：时间线，登录成功 / 失败 / 锁定 / 改密按时间倒序串联，每条记来源 IP、浏览器与系统（解析成「Chrome 141 · Windows 11」）以及**通过方式**（密码 / 密码 + 动态码 / 密码 + 恢复码 / 已登录会话 / 首次初始化）。
- **操作日志**：表格，时间 / 动作 / 对象 / 来源 / 设备五列对齐，凭据读取与明文导出混排，导出那一行整行标琥珀色。
- **安全事件**：告警卡，左侧色条标记严重度，带类别标签（验证失败 / 来源拦截 / API 鉴权 / 明文导出）与探测证据。
- **访问白名单**：只允许列出的地址打开后台，支持 CIDR 与 IPv6。本机回环永不拦截，所以写错规则时仍能登录改回来。

每个列表都有独立的筛选条：关键词（IP、设备、账号、详情，空格分隔为「且」）、时间范围（今天 / 近 7 天 / 近 30 天），再加一个该列表专属的下拉（结果、操作类型或事件类别），切换标签不会串味。列表都支持分页（每页 20 / 50 / 100）。IP 与设备信息从本次更新起采集，之前的历史记录显示为「来源未记录」。

### 访问白名单

在应用这一层拦截，不依赖反向代理：白名单之外的来源拿到的是 403，并在安全事件里留一行「来源地址不在白名单」。三种写法都认——单个地址 `203.0.113.7`、网段 `10.0.0.0/8`、IPv6 `2001:db8::/32`。

- 本机回环（`127.0.0.0/8`、`::1`）始终放行，`npm run admin:unlock` 与本地浏览器不会因为写错条目而失联。
- 启用前至少要有一条，空列表不让保存——那是「把自己锁在门外」的另一种写法。
- 想用环境变量播种首次配置，设 `ACCOUNT_DESK_ADMIN_ALLOW=1.2.3.4,10.0.0.0/8`；一旦在页面上保存过，就以页面为准，删掉的条目不会在重启后复活。
- 放在 nginx 后面时同时打开 `ACCOUNT_DESK_TRUST_PROXY=1`，否则这里看到的来源永远是 `127.0.0.1`。

### 通知推送

侧边栏「通知推送」进去后是六个小页面，用顶部标签切换，六件事互不挤在一起：

| 页面 | 内容 |
|---|---|
| **推送通道** | 邮件 / 钉钉 / 飞书 / 通用 Webhook，一张卡一条通道；右上角开关就是总闸，打开即推，关掉即停（不用进编辑里改状态）。没有通道时四种方式会以「未添加」卡片列出来，拨开开关就开始配置 |
| **发送记录** | 每次推送到哪条通道、成没成、失败原因，可按结果、时间、关键词筛 |
| **定时巡检** | 每天到点自动检查过期账号并播报，可改时间与「过期」的天数，也能立刻手动跑一次 |
| **群机器人** | 钉钉 / 飞书 / 通用 Webhook，一张卡一个群，带回调地址与启停开关 |
| **指令** | 群里能发哪些指令、各自做什么、限流多少 |
| **消息记录** | 谁在哪个群问了什么、机器人答了什么，可按方向、时间、关键词筛 |

- 所有列表页底部都有分页：共多少条、第几页、每页 20 / 50 / 100 条；只有一页时控件也在，方便提前调大每页条数。
- 订阅按「登录与解锁、账号与安全设置、凭据读取与两步验证、异常与渗透迹象、巡检与播报」五类勾选，卡片上只显示短标签，悬停看全称。
- 机器人**只读**：能查状态、触发检活、请求播报，永远不返回密码或两步验证密钥。
- 巡检报告只发给勾了「巡检与播报」的通道，不与登录告警混在一条时间线里。
- 回调地址里那串字符就是入口凭证，怀疑泄露时点「换地址」，旧地址立刻失效。

详见 [安全文档](docs/security.md#10-推送通知)。

## 导入格式

```text
name@example.com----password----username----JBSWY3DPEHPK3PXP
other@example.com----password----another-user
```

- 一行一个账号，可粘贴或读取 UTF-8 TXT 文件，每次最多 1000 行、1 MB。
- 第四段 TOTP 密钥可缺省或留空。密钥应为 Base32 格式，不是六位验证码；支持密钥内的空格和小写。
- 邮箱、用户名两端空格会去除；密码中的空格会原样保留。字段中不能包含分隔符 `----`。
- 导入前显示校验结果；有效且非重复行导入，无效行跳过。
- 邮箱和用户名大小写不敏感去重，重复记录不覆盖。回收站中的账号也占用其用户名和邮箱；可恢复后编辑。

## 已实现

- 紧凑账号列表：检测结果、来源分组、用途标签与任务用途分别展示；每页可选 15 / 25 / 50 / 100 条。
- 分组管理：创建、改名、删除、查看关联账号。一个账号一个来源分组；默认未分组。删除分组后账号自动回到未分组（含回收站），不删除账号。
- 标签管理：创建、改名、更换颜色、删除、查看关联账号。一个账号可带多个用途标签（最多 50 个），如项目名、已分配、待交付；删除标签仅移除标记。
- 导入和新增时选择分组及多个标签；已有账号可点击来源分组或在详情中「整理分类」，勾选后可批量移动分组、追加 / 移除 / 替换标签。标签不会自动改变选用占用或授权状态。
- 搜索支持账号、备注、来源和用途标签；分组、标签、公开检测、TOTP 可以组合筛选。切换筛选或账号移出当前结果时取消隐藏账号的勾选。
- 公开检测统一为未检测、公开可访问、公开不可访问、无法判断；无法判断显示请求受限或检测失败的原因。公开不可访问不能直接判定封禁。现有账号升级后保留资料与检测记录，默认未分组、无标签。
- 导入预览与错误行号、重复提示。
- 账号列表将来源分组、标签、TOTP、公开检测和入库时间分列展示；「显示列」勾选即生效，可恢复默认，按全部账号、WorkBuddy、PAT 和回收站视图分别保存浏览器偏好。
- 时间列支持入库、最近检测、选用、WorkBuddy 处理结束/关联、PAT 到期和回收站移除时间，统一北京时间；入库时间不是 GitHub 注册时间。支持用户名、入库时间、检测时间排序，空时间排最后。
- 列表分类为全部账号、可用、失效、未知、WorkBuddy2api、PAT 专用、任务占用。前三种状态按公开检测结果区分：可用为公开可访问，失效为公开不可访问，未知为检测失败或请求受限；未检测仍有独立筛选。任务与检测分类允许交叉，不表示可重复选用。
- 「任务占用」仅展示仍保留任务占用的账号，包含等待人工处理的任务，默认显示任务状态列。普通历史选用标记不算运行中的任务；原有防重复选用规则保留。
- WorkBuddy 待执行/执行中自动刷新，成功关联不因后续失败而消失。旧版「远端账号池已存在（用户确认）」登记，只有当前选用信息与最近选用事件的账号、用户名、内容、时间均匹配时才归入 WorkBuddy，显示「外部已登记」与登记时间，不生成虚假的 UID 关联。
- WorkBuddy 工作台显示执行统计、操作与日志，移除任务记录选择器和账号结果面板；账号详情和任务状态仍可进入对应任务日志。PAT 管理由侧栏进入，列表不再重复显示顶部入口和「选用一个账号」。
- 检测完成提示 5 秒后收起，后台读取不会重新弹出同一结果；中断或可继续的任务保留操作入口。TOTP 已设置使用绿色，未设置使用琥珀色。
- 单个新增账号；支持邮箱、用户名、密码、可选 TOTP 和备注。
- 列表提供独立“详情”和“编辑”入口，均为居中弹窗。详情只读查看、复制及自动检测；编辑中修改邮箱、用户名、密码、TOTP 和备注，保存后生效。
- 未保存的编辑 / 新增、退出导入、释放选用标记使用统一站内二次确认弹窗，不再弹出浏览器原生确认框。取消或 Esc 保留输入，明确确认放弃后才关闭。
- 四个核心字段均可单独复制，复制密码 / 密钥无需先显示。凭据默认隐藏，按需显示 30 秒后隐藏；切换浏览器标签页也会隐藏。当前验证码可生成、复制及刷新。
- 程序通过 GitHub 接口执行公开活性检查。列表行与详情均有单个检查入口；勾选后可“检查选中”；“检查全部”由服务端读取账号库，不受搜索、筛选、分页影响，不含回收站，也没有 1000 条检查上限。
- 检查队列提供进度条、当前账号、可访问 / 不可访问 / 请求受限 / 检查失败 / 跳过 / 未检查数量，支持取消，结果与时间保存到数据库。
- **检测筛选结果**覆盖当前搜索与筛选的全部分页；**检测设置**支持多条命名规则，每条可单独启停，并按状态、来源分组和标签筛选。预览显示启用规则的去重范围与到期数量，同一账号命中多条规则只检测一次。手动单个、勾选及范围检测不受到期时间限制，弹窗范围检测不保存草稿。
- **自动检测**默认关闭，支持两种模式：固定间隔按最近检测时间计算，间隔为 1–365 天；分阶段按导入日期或指定基准日期计算，默认第 1、3、7、15、30 天检查，之后每 30 天检查，节点与后续间隔均可修改。日期统一按北京时间，例如基准 10 月 20 日，第 1 天是 21 日，第 3 天是 23 日；导入日期不是 GitHub 注册日期。手动确认结果也覆盖已到期节点，错过多个节点只补查一次，失败不推进阶段。
- 新规则默认包含可用、未知、未检测，排除失效和回收站；新老账号可用不同分组配置不同规则。原有单条设置迁移为“默认规则”，保留开关、间隔及筛选。服务每分钟检查一次；关闭网页不影响后台，关闭电脑/服务后暂停，重新启动后补查到期账号并接续未被手动取消的自动任务。
- 自动检测与现有检测/授权任务互斥，手动取消的未完成任务保持暂停，可点击继续检查。网络、服务或资料异常保留上次结果，按 30 分钟、2 小时、6 小时退避；延长检测周期也会重新计算到期时间。仅保存设置、当前队列及每账号最近尝试状态，不累计操作历史。
- 启用 PAT 使用时，每次新检测任务随机选择一个已验证的 PAT 账号。普通账号额度耗尽后自动换用有额度的账号，接着未完成位置检测；全部耗尽则等待最早恢复时间。额度按 GitHub 账号共享，二级限流或 Retry-After 保持全局等待，不会通过切换账号或关闭 PAT 使用跳过等待。进度显示当前 PAT 用户名，不显示 Token。
- 手动指定 / 自动选用候选账号，即时登记用途和时间，数据库事务防止重复选用，支持手动释放。
- 列表快捷移除、勾选批量移入回收站、单条 / 批量恢复。每次移除都有确认弹窗，可全选当前页或当前筛选结果；切换筛选会清除旧勾选，避免误操作。
- 不再记录通用操作历史；旧数据自动清理，必要的 WorkBuddy 归属单独保留。
- 桌面和窄屏布局，键盘焦点、原生对话框、减少动态效果支持。

## WorkBuddy2api：国际版 GitHub OAuth

仅支持国际版 Global，国内版不支持 GitHub 授权。先运行 `npm run browser:install`，将 Playwright 配套的 Chromium 下载到项目 `.local-browsers/`（约 200 MB 下载量）。程序仅启动此专用浏览器，不调用本机日常 Edge/Chrome，不读取个人浏览器配置、扩展、Cookie 或登录状态。缺失时提示安装，绝不自动回退使用日常浏览器。更新 Playwright 依赖后请重新运行安装命令。

配置弹窗仅维护一条连接，包含部署地址、API Key、连接方式（直连/代理）；保存后直接修改，不再新建或切换多个配置。选择代理后只需粘贴完整链接，自动识别 HTTP、HTTPS、SOCKS5 和认证信息，例如 `http://127.0.0.1:7890`、`http://用户名:密码@主机:端口`、`socks5://用户名:密码@主机:端口`。密码中的 `@`、`#`、`%` 等特殊字符建议使用 URL 编码（如 `%40`）。用户名、密码加密保存，代理链接输入默认隐藏；保存后不回填密码，留空保留整条原配置。输入新链接会整体替换代理，输入无认证链接会移除旧认证。切换直连并保存会清除代理配置。

代理作用于授权浏览器和浏览器网络测试，不修改系统设置，不代理远端面板 API。直连明确绕过系统代理（原未配置代理的记录现在按直连处理）；需要本机代理时填写本机代理端口。带认证 SOCKS5 使用仅监听 `127.0.0.1` 随机端口的临时转接，并由 SOCKS 服务解析目标域名；启动失败、测试结束或任务关闭时释放转接端口和连接，不会失败后回退直连。代理失败在同一网络配置内重试，超限后跳过当前账号；运行中的目标禁止修改配置。每个账号新建独立临时会话，结束即关闭，不存储跨账号登录状态。“测试连接”同时检查部署 API 和浏览器访问 GitHub 登录页，分别显示结果；不登录账号，不执行 OAuth。网络测试成功不代表账号授权一定成功。

1. 先在“账号管理”检查账号公开状态。
2. 进入 **WorkBuddy2api → 右上角配置**，填写 HTTPS 部署地址、远端 `api_key`（或 `WB2A_API_KEY`），按需选择代理。与原项目面板填写的密钥相同，不是 GitHub 密码/PAT；部署域名不写死。可填根地址或 `/panel/` 地址，支持反向代理子路径。
3. 保存后“测试连接”：携带 `Authorization: Bearer <API Key>` 请求 `GET /panel/api/overview`，同时用独立无登录浏览器检查直连或代理。修改未保存时需先保存再测试。API Key 无内建过期，远端改密钥后需在这里更新。本机加密保存，不回显、不存入浏览器 localStorage；修改时留空保留原密钥，更换服务地址必须重新填密钥。
4. 输入账号数量（1–100）。**第一次建议仅 1 个**，先验证线上页面兼容性。点击“开始”，在居中确认框检查部署地址、具体账号和远端操作后果；取消不会调用远端。
5. 程序临时占用本次候选账号，依次调用 `POST /panel/api/login/start`，JSON 固定 `{"realm":"global"}`；打开独立可见浏览器会话、选择 GitHub，填写已保存密码和新生成的 TOTP。每个账号使用独立会话，不共用默认浏览器登录状态。
6. 每个账号最多尝试 4 次，重试间隔为 3、6、9 秒，处理时限 180 秒（包括取链接、启动浏览器、授权与确认入池）；浏览器清理最多额外等待 10 秒。导航网络错误会自动重试失败的可信 GET 页面，不重放密码/授权 POST 或带 code 的回调。GitHub 邮箱设备验证（`/sessions/verified-device`）立即记录原因并跳过，不用 TOTP 代填邮箱验证码，也不重发邮件。人机验证、未知页面、缺少 TOTP 等无法自动完成时，有限重试后记录未知结果、关闭浏览器、释放当前占用并继续下一个账号。身份变化或不匹配直接跳过，不等待人工操作，也不会猜测成功。授权按钮支持 `Authorize` 和 `Authorize <组织名>`；点击前先自动滚动并等待可点击，等待失败不标记为已提交。真正的点击结果不明时保留防重复提交保护，继续核对回调。失败诊断仅记录固定阶段名、当前文档 HTTP 状态及身份/回调证据是否成立，不记录授权 URL、验证码、Cookie 或页面正文。
7. 核验 GitHub 用户名及官方 WorkBuddy OAuth 回调后，调用 `GET /panel/api/login/poll?state=...`。只有返回有效的 `done:true`、`realm:global`、UID，才在同一事务保存 UID 关联并标记本地账号已使用。拿到链接不算成功，不根据远端昵称匹配 GitHub 账号。

**重要：远端 poll 虽然是 GET，却有写入副作用。** 上游源码会保存凭证、加入/恢复账号池；Global 还可能自动注册激活、补地区（例如 HK）、领取 trial 并更新资源信息。开始确认框会披露这些行为。本机不额外调用领取接口；仅在你明确确认后运行该上游流程。请只使用你本人或明确获授权的账号，并遵守服务条款。

任务和结果仍持久化，页面刷新不会重复创建任务；工作台不再显示任务历史列表，可从账号进入相关任务日志。全局同时只执行一个授权任务（与旧版仅取链接任务互斥），重复提交有幂等保护。工作台页面轮询的是本机任务状态，不会由网页反复调用远端入池接口。

「清空显示」按任务在当前浏览器保存日志显示位置，刷新页面或重启本地服务后仍有效；只隐藏已显示的旧日志，新增日志继续显示，其他任务互不影响。历史日志仍保留在数据库中。清除浏览器站点数据或换浏览器后，此显示偏好会重置。

- WorkBuddy 显示“访问受限”：保存受限记录并排除后续 WorkBuddy 自动选择，跳过当前账号继续队列；不修改 GitHub 公开检查结果。
- 点击“停止”：关闭当前浏览器并取消后续账号；已发生的远端授权/入池不会撤销。
- 远端鉴权错误、权限拒绝、限流、请求超时、格式异常或 UID 冲突：记录当前账号未完成并继续后续账号；不重复提交同一账号的 start 或结果不明的 poll，避免重复入池。
- 远端明确返回尚未完成时，保存未知结果并继续。服务重启不重放远端请求，未完成账号自动释放占用，结果记录保留。
- 失败原因保留在任务日志与账号结果中；未知结果不会当作成功，也不会等待人工核对才继续队列。
- 授权中的账号不能编辑、删除、手动选用或释放；成功关联保存后，即使手动释放普通选用标记，也不会再次纳入 WorkBuddy 自动候选。

授权链接/state 是临时敏感凭据，服务端加密保存，不出现在任务日志。上游的 state 清理阈值约 15 分钟，远端重启也可能使其失效。浏览器页面选择器或 OAuth 参数变更时会有限重试后跳过；**当前完成源码对接及模拟流程验证，未使用真实 API Key 完成线上端到端授权**。

**熔断**：如果连续 2 个账号都卡在同一个结构性环节（未识别 GitHub 登录入口、无法唯一确认入口、必需协议未确认、未识别授权按钮、回调缺少身份证据），任务会立即停止并把后续账号标记为已跳过，任务消息提示「疑似上游授权页面改版」。这样可以避免上游改版后按每账号 4 次尝试、180 秒上限把所有账号空跑一遍；普通失败（登录未完成、人机验证、网络错误）不触发熔断，仍按原逻辑继续下一个账号。成功一个账号即清零计数。

旧版仅获取链接的数据库记录保留，不覆盖或自动续跑。

## 检查结果的边界

| 结果 | 含义 |
| --- | --- |
| 公开可访问 | GitHub `GET /users/{username}` 返回匹配的个人账号资料 |
| 公开不可访问 | 404；可能更名、删除或受限，不足以认定封禁 |
| 请求受限 | 403 / 429；接口限流或拒绝请求，不能判定账号风控 |
| 检查失败 | 超时、网络错误、其他异常响应，不能判定账号风控 |

**公开可访问 ≠ 无风控 ≠ 能正常登录。** 已移除人工审核与风控标记，结果由程序检测并保存。更改用户名会清空原公开检查结果。未经认证的 GitHub API 通常每 IP 每小时 60 次请求，遇到限流会停止队列；本机网络也可能影响检查。检查只发送用户名，不发送邮箱、密码或 TOTP。

候选条件：最近 24 小时检查为公开可访问、未选用且未被授权任务占用。WorkBuddy 候选还会排除已保存成功关联的账号。旧人工标记不再影响候选筛选，数据库旧列和历史记录保留。手动“选用”按钮仍只登记记录，不会启动 OAuth。

## 数据与备份

正式数据存储在项目 `data/` 中：

- `accounts.sqlite`：账号、检查结果、部署配置、授权任务、临时占用及远端 UID 关联。
- `master.key`：AES-256-GCM 加密密钥。
- `runtime-lock.sqlite`：运行互斥锁文件，防止多个服务同时使用同一数据目录；进程退出或异常终止后锁由系统释放，不要在运行中删除它。
- SQLite 运行时可能存在 `accounts.sqlite-wal` 和 `accounts.sqlite-shm`。

**停止服务后**，推荐使用内置命令备份与恢复（自动执行 WAL checkpoint，保证快照自包含）：

```powershell
npm run backup          # 备份到 backups/manual-<时间戳>（可传自定义目录参数）
npm run restore <目录>   # 恢复指定备份；现有数据会先移到 <数据目录>.before-restore-<时间戳>
npm run harden:data     # 把 data/ 收紧到仅当前用户、SYSTEM、Administrators 可访问
npm run check:data      # 只检查不改动，权限过宽时退出码为 1
npm run admin:unlock    # 清除所有登录锁定（被锁在外面且没有已登录窗口时使用）
```

两个命令都会检测运行中的服务（runtime-lock 被占用时拒绝执行），避免备份到正在写入的数据库。恢复要求备份中必须包含 `master.key`，否则拒绝执行。手动备份亦可：停止服务后复制整个 `data/` 目录。恢复时同样停止服务，恢复整套数据库和密钥。密钥丢失后无法解密密码 / TOTP；程序检测数据库存在但密钥丢失时会拒绝启动，避免误生成新密钥。

**备份目录等同明文**：备份必然包含 `master.key`，因此和 `data/` 一样敏感。`npm run backup` 默认写到项目下的 `backups/`（不再写进权限较宽的 `output/`），并在复制完成后立即把目录收紧到仅当前用户、`SYSTEM`、`Administrators`；收紧失败会以非零退出码报错。不要把备份放进网盘同步目录或 Git 仓库；需要异地保存时请先自行加密（例如放进加密卷或压缩包加密码）。

密码、TOTP、项目 API Key 和授权 URL/state 加密；邮箱、用户名、备注、项目地址和任务摘要是普通数据库字段。密钥与数据库在同一机器，因此这不能防范同时读到两者的人。后台使用单管理员登录，可按部署文档通过 HTTPS 反向代理提供服务。浏览器接口校验会话、来源、Host 和写请求 CSRF token，禁用缓存及跨站访问，但无法防止本机有权限运行的其他程序读取数据。复制到系统剪贴板的内容由系统保管。

针对入侵的加固集中在 [安全加固文档](docs/security.md)，包括登录防枚举、递增锁定、会话空闲超时与批量下线、读取明文凭据的二次验证与审计、可选的管理员两步验证（TOTP + 一次性恢复码）、安全事件留痕、响应头、公开 API 写入限流，以及数据目录权限收紧；文档也列出了**明确没做**的部分。

`data/`、`backups/`、`output/`、`.env` 已加入 Git 忽略。测试使用独立临时数据库；浏览器验证使用 `output/qa-data/`，不影响正式数据。

### PAT 管理

左侧 **PAT 管理** 与 WorkBuddy2api 并列，进入后直接查看账号与记录列表：凭据保存状态、验证结果、剩余额度、实际上限、到期时间和具体诊断。右上角 **PAT 配置** 设置自动补充开关与目标数量（可填写 1–100 的整数）；冷却及待验证的凭据仍计入维护数量。

保存配置后，可在此页点击 **新增 PAT**。任务依次显示登录与两步验证、权限核对、生成与保存、身份与额度验证。遇到真正的人工验证时，在独立浏览器处理后点击 **继续 PAT 浏览器**；检查队列的继续操作仍在账号管理页。停止、停用凭据和释放账号用途是不同操作，页面会分别说明影响。

### PAT 中断恢复

“PAT 专用”表示账号用途已保留，不代表 Token 已经生成。没有到期时间、额度且状态为“需处理”时，应查看具体诊断。

Windows 上，服务重启后，未提交创建、未保存 Token 的旧任务可在下次“新增 PAT”或“继续检查”时自动恢复：先确认所有项目 Chromium（包括旧版本）均已退出，再复用原账号和原记录，不需要释放专用用途或重新选号。启动服务本身不会登录 GitHub。已经达到维护数量时，只结束未提交的旧任务，不额外创建 Token。

进程信息不可读取、项目浏览器仍在运行或平台不支持退出检查时，保留占用。已经提交但结果未知的记录禁止重放；邮箱验证、人机校验以及未适配的 GitHub 页面仍可能需要处理。本地模拟测试通过不代表真实 GitHub 创建已经完成。
- `docs/`：设计、实施计划和验证记录。

Node.js 22 可能输出 SQLite experimental 提示，这是内置 SQLite 模块的提示，不代表启动失败。

PAT 配置保存成功后自动关闭。列表自动刷新，支持搜索账号、邮箱、备注及按状态筛选；记录可编辑账号备注、停用、释放用途，已停用或已释放的记录可确认删除。删除只清理本地记录与加密凭据；远端凭据仍可能有效时，仅保留到期时间与账号专用保护，防止重复选用。无记录的专用账号仍可在页面释放（需已无有效或未知凭据）。

回收站支持永久删除选中账号和清空全部回收站。确认后清理账号凭据、分组标签关联、PAT 及 WorkBuddy 本地关联，并移除检测队列中的相应条目；在事务提交后尝试压缩数据库文件。正在运行的任务会阻止永久删除。不会删除手动备份文件，也不执行远端撤销。
